# 虚构闭环演示

以下对象、命令和数值全部用于解释流程，没有真实执行，也不属于当前 Research Memory。不要复制进活动索引或 State 当作证据。

## 1. 讨论可以发散

假设研究者在研究固定模型的数据处理耗时：

- IDEA-101：缓存确定性的预处理输出。
- IDEA-102：更换更大的模型。
- IDEA-103：删除部分评估样本来缩短时间。

IDEA-101 被选中，因为可以保持模型和评估对象不变。IDEA-102 因预算 Parked，并非被科学否定。IDEA-103 因改变评估范围被 Rejected；如果研究目标变化可以重新讨论，不能说它“被实验证伪”。

DEC-101 记录取舍，HYP-101 才进入活动状态；整个 brainstorm 不进入 State。

## 2. 可证伪的命题和设计

HYP-101：指定硬件、数据与模型下，缓存预处理让指定工作负载的平均耗时减少至少 20%，且输出满足预先定义的一致性检查。

| EXP-101 r1 项目 | 内容 |
| --- | --- |
| Question | 缓存是否产生至少 20% 的耗时降低？ |
| Manipulation | 仅缓存开关变化 |
| Control | 模型、数据、批大小、硬件、线程、预热与计时边界 |
| Sampling | 同一 workload 配对重复、顺序随机；真实任务须事先论证重复数与不确定性方法 |
| Metric | 相对耗时降低，正值表示更快；输出一致性是有效性条件 |
| Expected | 预定区间下界 ≥ 20%，有效性检查通过 |
| Falsification | 区间上界 < 20%，有效性检查通过 |
| Inconclusive | 区间跨越 20% |
| Invalid | 输出不一致、划分变化或计时失效 |
| Alternative explanation | OS 缓存、预热顺序、额外内存、数据分布 |
| Ablation | 按预定矩阵比较无缓存、仅输入缓存、完整预处理缓存 |

阈值与分类只是演示，不是通用统计建议。真实项目须论证独立单位、抽样与不确定性方法。“耗时降低 20%”也不等于“加速比 1.2”，需要固定指标定义。

## 3. 生成 Update 和独立 Task

Update 的变更包括：3 个 Idea 的登记、DEC-101、尚无直接实验证据的 HYP-101、EXP-101，以及 State 的局部摘要。EXP-101 的抽样、命令和预算未补齐前保持 Draft。

局部补丁示例：

    Target: RESEARCH_STATE.md > Active Hypotheses
    Operation: Replace exact
    Before: - None。
    After: - HYP-101：缓存降低耗时至少 20%；Active；尚无直接证据。详见 HYPOTHESES.md。
    Reason: DEC-101 选定问题，EXP-101 用于检验。

Before 必须来自真实基线。演示里的 Before 不能直接用于当前工作区，因为原文不同。

另建 TASK-101，其 Context 包含 State、HYP-101、DEC-101 和 EXP-101。任务验收分别是：

- Functional：开关、输入输出、缓存失效与错误处理符合定义。
- Scientific：忠实执行固定设计，完整保存全部变体、重复、尝试、快照和指标。
- Regression：无缓存行为保持原契约，缓存输出通过一致性检查。

“必须提升 20%”不能成为任务完成门槛。它是科学假设判据，任务必须允许如实报告负结果。

## 4. 事实与解释分开返回

假设一条演示 RUN 记录：平均耗时降低 9.4%，预定区间 [7%, 12%]，输出一致性通过，设计要求均满足。数值为人为构造，没有真实测量。

- results/RUN-示例/RESULT.md：记录测量、区间、计数、有效性检查和产物位置。
- reports/TASK-示例.md：工程验收通过、结果完整交付，任务可 Done。
- analyses/RUN-示例.md：根据 EXP-101 r1，区间上界低于 20%，当前操作化命题被反驳。

解释仅限于当前测试环境，不能推导“缓存永远无效”。若区间为 [5%, 25%]，则 Inconclusive；若输出不一致，则 Invalid，而不是 Refuted。
